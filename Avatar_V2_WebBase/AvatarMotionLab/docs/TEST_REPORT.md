# گزارش آزمون و حدود تأیید

تاریخ تهیهٔ بسته: ۱۴ اکتبر ۲۰۲۶

## نتیجهٔ واقعی آزمون‌ها

**۳۶ آزمون Node.js موفق، صفر آزمون ناموفق** در اجرای نهایی. خروجی خام در `test-results.tap` موجود است. فرمان قابل تکرار، از پوشهٔ اصلی پروژه:

```powershell
node --test
```

بررسی syntax با `node --check` برای تمام فایل‌های JavaScript برنامه، ابزارها و آزمون‌ها انجام شد. محیط آزمون Node.js نسخهٔ 22.16.0 روی Linux بود؛ اجرای فایل CMD در ویندوز مستقیماً آزموده نشده است.

| حوزه | آنچه واقعاً آزموده شد | نتیجه |
|---|---|---|
| جهت حرکت و محاسبات | حرکت نسبت به دوربین، حذف افزایش سرعت قطری، زاویه و هموارسازی | موفق |
| حرکت و پرش | سرعت راه‌رفتن/دویدن، ترمز، مراحل پرش و فرود، جلوگیری از پرش دوم در هوا و بافر پرش | موفق |
| برخورد | توقف پشت مانع، لغزش کنار دیوار، پلهٔ کم‌ارتفاع، مانع بلند، فرود روی سکو، مرز محیط، reset | موفق |
| منطق صورت | شش الگوی مجزا، وزن‌های محدود، گذار نرم، پاک‌شدن احساس قبل، پلک، کنترل دستی و اتصال روی چند mesh شبیه‌سازی‌شده | موفق |
| دادهٔ GLB | خواندن دادهٔ نمونهٔ مصنوعیِ آزمون، تشخیص ورودی خراب، خواندن accessor و استخراج سه clip بدون mesh | موفق |
| سرور | index/MIME، وضعیت فقدان assets، HEAD، ممنوعیت دسترسی به ابزار سرور، کنترل path traversal، رد POST، خطای 404 و no-sniff | موفق |

**این آزمون‌ها از فایل واقعی AvatarSDK یا مدل Xbot استفاده نکرده‌اند.** آزمون morph، اتصال و وزن‌ها را روی ساختار مصنوعی بررسی می‌کند، نه کیفیت تغییرشکل پوست واقعی. آزمون استخراج انیمیشن نیز fixture مصنوعی دارد. نتیجهٔ موفق آن، تطبیق بی‌نقص همهٔ مدل‌های GLB را اثبات نمی‌کند.

## رابط کاربری

۸ بررسی دیگر با Chromium/Playwright روی DOM محلیِ HTML/CSS و وضعیت خطای شبیه‌سازی‌شده انجام شد. این بررسی‌ها به فایل مدل یا اینترنت وابسته نبودند:

- نمایش حالت بارگذاری، نمایش دکمهٔ بررسی وضعیت پس از خطا، نمایش نام راه‌انداز ویندوز و حفظ پیام فنی خطا.
- نبود سرریز افقی کل صفحه و حفظ عرض قابل استفادهٔ viewport در اندازه‌های 1440×960، 1280×720، 1024×768 و 390×844.

خروجی خام در `ui-shell-results.json` موجود است. صفحه به‌صورت HTML در حافظهٔ مرورگر بارگذاری شد. این آزمون، رابط اجراشده همراه کاراکتر یا عملکرد WebGL را تأیید نمی‌کند؛ دکمه‌های پویای ساخته‌شده پس از بارگذاری مدل نیز موضوع این آزمون نبودند.

## مواردی که تأیید نشده‌اند

دریافت فایل‌های باینری از شبکه در محیط ساخت ممکن نبود. همچنین تلاش برای پیمایش مرورگر آزمایشی به سرور محلی با `ERR_BLOCKED_BY_ADMINISTRATOR` مسدود شد. آزمون HTTP سرور با Node.js مستقل موفق بود، اما اجرای مرورگرِ کامل از روی سرور در این محیط انجام نشد.

در نتیجه، این موارد **آزمون عملی انتهابه‌انتها ندارند**:

- موفقیت دانلود وابستگی‌ها از رایانهٔ کاربر و مسیر کامل first-run installer؛
- رندر واقعی GLB، درستی جهت بدن/استخوان‌ها، پوشش نام‌های مفاصل و کیفیت retarget؛
- ظاهر واقعی شش احساس روی صورت، لغزش پا، پارگی یا نفوذ هندسی اندام‌ها؛
- نرخ فریم، مصرف حافظه، زمان بارگذاری، اندازهٔ نهایی بستهٔ آفلاین و سازگاری مستقیم Windows CMD؛
- واقعی‌بودن یا کیفیت سینمایی چهره و حرکت.

توسعهٔ بخش‌های بالا در کد انجام شده، اما ادعای تأیید بصری یا عملکرد محصول نهایی برای آن‌ها مطرح نمی‌شود.

## چک‌لیست پذیرش پس از راه‌اندازی اولیه

| آزمایش دستی | انتظار |
|---|---|
| اجرای `node start.mjs` | دریافت فایل‌ها و بازشدن صفحه بدون خطای قرمز Console |
| بازکردن F | صورت از جلو، چشم‌ها و دهان قابل مشاهده؛ نه پشت سر یا داخل هندسه |
| 0 → 1 → 2 → 3 → 4 → 5 | شش حالت قابل تفکیک، گذار تدریجی، نبود پارگی هندسهٔ لب و پلک |
| B و تعجب | بسته‌شدن و بازشدن پلک، بدون بازماندن افراطی چشم در حالت پلک |
| W و سپس Shift | انتقال راه‌رفتن به دویدن، حفظ اندازهٔ بدن و تماس معقول پا |
| رهاکردن ورودی | کاهش سرعت و بازگشت به idle |
| حرکت به دیوار | توقف جابه‌جایی، کاهش انیمیشن حرکت و عدم عبور بدن |
| Space درجا و حین حرکت | آماده‌سازی، بلندشدن، فرود؛ بدون پرش دوم در هوا |
| حرکت روی سکو | تماس کفش با سطح، نبود عبور از مانع بلند |
| F/V/C، چرخاندن ماوس و zoom | دوربین قابل کنترل، تغییر حالت تدریجی و فاصلهٔ مناسب از دیوار |
| خاموش/روشن‌کردن Foot IK | مقایسهٔ لغزش پا و تماس؛ ثبت موارد بدشکلی برای اصلاح rig |
| حذف فوکوس پنجره در حال حرکت | باقی‌نماندن کلید در وضعیت فشرده |
| اجرای دوباره با `--offline` و قطع اینترنت | شروع برنامه با assets ذخیره‌شده و بدون درخواست بیرونی |

برای اطلاعات تشخیصی، در DevTools مرورگر:

```js
window.__avatarLab.snapshot()
```

خروجی شامل وضعیت حرکت، موقعیت، تعداد پرش‌ها، حالت دوربین، نام احساس، شمار morphهای خوانده‌شده، کانال‌های گمشده، تعداد استخوان‌های تطبیق‌یافته و آمار مدل است. داده‌ای ارسال نمی‌شود. این API فقط در صورت راه‌اندازی موفق بخش سه‌بعدی ایجاد می‌شود.

## معیار واقع‌گرایی

«وزن‌های صورت درست محاسبه می‌شوند» با «چهره کاملاً واقعی دیده می‌شود» یکسان نیست. همچنین «فیزیک پرش آزمون را می‌گذراند» به معنای «حرکت بدن موشن‌کپچر است» نیست. این نسخه باید پس از دریافت مدل با چک‌لیست فوق بررسی شود؛ برای کیفیت نهایی، اصلاح مدل/retarget و احتمالاً حرکت‌های اختصاصی لازم خواهد بود.
