# تحویل قابل انتقال آواتار ترکیبی — 0.1.2

این تحویل، Plugin آواتار ترکیبی پذیرفته‌شده در مرحلهٔ ۱۹ اکتبر ۲۰۲۶ و منبع میزبان مستقل آن را آماده می‌کند. نسخهٔ فنی Plugin برابر `0.1.2` و قرارداد برابر `1.0.0` است. آماده‌سازی فایل‌ها به معنی upload، ارسال برای بررسی یا انتشار Registry نیست؛ وضعیت Git و سرویس‌ها از رسید مستقل همان عملیات خوانده شود.

## محتوا و مرز پذیرش

`آواتار/` شامل کد، typeها، dist، منابع مدل و حرکت، اسکریپت ساخت، آزمون‌های مستقل، راهنمای مصرف، lockfile و اعلان‌های حقوقی است. export جدید `AvatarHybrid` و runtime آن کنار رابط‌های قبلی حفظ شده‌اند. بدن/لباس و هشت حرکت V1، پرش V2 و صورت تازهٔ مبتنی بر توپولوژی V2 با ۶۶ morph بومی و ۳۷ کنترل جاری در همین مسیر قرار دارند. گفتار، lip-sync صوتی، گرفتن جسم، پنج انگشت مستقل بدن V1 و Quest/XR تحویل این مرحله نیستند.

`avatar-lab/` میزبان نمونه با Player Rig دقیق نسخهٔ `1.0.0` و وابستگی `file:../آواتار` است. فقط کد تولید، آزمون‌های مستقل، کاور و مستندات دقیق Plugin مصرف‌شده کپی می‌شوند؛ `HybridTest*`، `MotionTest*`، آزمایش‌های قدیمی، junction، node_modules و نشست محلی داخل تحویل نیستند. داده‌های عمومی مدل و dist میزبان هنگام ساخت از exportهای بسته تولید می‌شوند.

`verification/acceptance-summary.json` خلاصهٔ پذیرش قبلی مالک و digest همان ساخت را ثبت می‌کند. گزارش تاریخی `acceptance/AVATAR_HYBRID_PHASE2_FA.md` جزئیات و حدود شواهد را نگه می‌دارد؛ مسیرهای شواهد خام آن به workspace اصلی مربوط‌اند و همگی جزو این کیت نیستند. تصاویر یا آزمون نمایشی تازه برای بازسازی پذیرش مالک اجرا نشده‌اند.

## بازتولید مستقل

از ریشهٔ همین کیت:

```powershell
npm --prefix './آواتار' ci
npm --prefix './آواتار' run build
npm --prefix './آواتار' test
npm --prefix './avatar-lab' ci
npm --prefix './avatar-lab' test
npm --prefix './avatar-lab' run build
```

آزمون تطبیق با آزمایش پذیرفته‌شده در ریپوزیتوری اصلی اجرا می‌شود و به‌دلیل نیاز به آن سابقه، جزو آزمون مستقل کیت نیست. شمار آزمون‌های `verification/plugin-tests.json` مربوط به بررسی ریپوزیتوری است؛ نتیجهٔ نصب/ساخت مستقل فقط وقتی `portable-copy.json` موجود باشد، از همان رسید خوانده شود. این رسید پیش‌شرط ساخت کیت نیست.

پس از نصب الامر، اجرای Desktop را از پوشهٔ `avatar-lab` و launcher رسمی ثبت‌شده در `AGENTS.md` آن انجام دهید. انتخاب Plugin برای آماده‌سازی در الامر، پوشهٔ **`آواتار`** است که `al-amr.plugin.json` در سطح اول آن قرار دارد؛ ریشهٔ کیت یا میزبان جای آن نیست. `alamr test` عملیات بارگذاری candidate است و آزمون محلی npm محسوب نمی‌شود.

## بررسی بسته و تغییرات بعدی

`tools/prepare-hybrid-release.mjs` در workspace اصلی، تنها پس از نسخهٔ هماهنگ `0.1.2`، آزمون‌ها، validate و بررسی artifact موفق، مسیر تازهٔ `releases/avatar-hybrid-0.1.2` را می‌سازد و در صورت وجود آن متوقف می‌شود. `release-inventory.json` اندازه و SHA-256 همهٔ فایل‌های snapshot، به‌جز خود inventory را ثبت و read-back می‌کند. نصب node_modules، ساخت میزبان یا افزودن رسید بعدی، خارج از آن snapshot اولیه است.

گزارش publish-doctor ممکن است با وجود موفقیت artifact، در حساب یا اتصال Registry مانع جداگانه داشته باشد. نتیجهٔ کلی و جزئیات همان رسید را بخوانید؛ اعتبار بسته، ورود حساب، مصرف نسخه، ارسال و انتشار نهایی یک وضعیت واحد نیستند. این ابزار هیچ‌یک از وضعیت‌های راه دور را حدس نمی‌زند و نسخه را تغییر نمی‌دهد.

## حقوق کد و دارایی

MIT فقط کد برنامه و adapter را پوشش می‌دهد. مدل، بافت و motion حقوق جداگانه دارند. نمونهٔ AvatarSDK در منبع بالادستی برای استفادهٔ غیرتجاری معرفی شده؛ این تحویل مجوز مستقل تجاری یا بازتوزیع عمومی ایجاد نمی‌کند. منابع V1 از ورودی مالک حفظ شده‌اند و مجوز اضافی برای دارایی‌های آن‌ها ادعا نمی‌شود. فایل‌های `آواتار/LICENSE`، `CODE-LICENSE.txt`، `THIRD_PARTY_NOTICES.md` و provenance کنار دارایی‌ها باید همراه بسته بمانند.
