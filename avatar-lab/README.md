# محیط مقایسهٔ آواتارهای الامر

این Environment مرجع اصلی V1 و آواتار ترکیبی پذیرفته‌شده را در همان صحنهٔ مشترک نمایش می‌دهد. آواتار جدید از export عمومی `AvatarHybrid` در Plugin نسخهٔ `0.1.2` و Player Rig رسمی و دقیق `1.0.0` استفاده می‌کند: لباس و حرکت‌های غیرپرش V1، پرش V2 و چهرهٔ تازه با توپولوژی و قابلیت‌های صورت V2.

## اجرا و کنترل

برای checkout کامل، ابتدا وابستگی‌های Plugin و این میزبان را با `npm ci` نصب و Plugin را با `npm --prefix ../آواتار run build` بسازید. سپس در این پوشه `npm test` و `npm run build` را اجرا کنید. ساخت میزبان، Plugin نصب‌شده را مصرف می‌کند و خودش کد پوشهٔ همسایه را نمی‌سازد؛ بنابراین کیت مستقل با وابستگی فایل/بستهٔ آمادهٔ `0.1.2` نیز کار می‌کند. مسیر CLI دقیق در AGENTS.md است.

از ریشهٔ پروژه `Open-Avatar-Lab.cmd` محیط اصلی `dist/` را باز می‌کند. نمونهٔ محلیِ پذیرفته‌شده خروجی مستقل `dist-hybrid-test/` دارد و مسیر اجرای آن در گزارش مرحلهٔ دوم ثبت شده است؛ این دو خروجی را یکی فرض نکنید.

- «تعویض آواتار» یا V: تغییر نسخهٔ تحت کنترل، با حفظ هر دو نمونه.
- «نمای هر دو»، «دنبال‌کننده»، «صورت» و «پا و زانو»: دوربین‌های بررسی.
- W/A/S/D، Shift، Space، F و Ctrl: حرکت، دویدن، پرش، پرواز و پایین‌آمدن در پرواز.
- «بازگشت هر دو» یا R: قرارگرفتن دوبارهٔ مدل‌ها در دو جایگاه جدا.
- «نمای فیلم» یا H: پنهان‌کردن پنل؛ Esc آن را برمی‌گرداند. ضبط و ارسال ویدیو خودکار نیست.
- آواتار ترکیبی: هشت کلیپ اصلی غیرپرش، احساسات، شدت، بازشدن فک، پلک و تنظیم نگاه/حرکت ظریف صورت در پنل موجودند.

فقط یک PlayerRig ورودی و دوربین را مدیریت می‌کند. دو controller، موقعیت مستقل دارند؛ تغییر انتخاب، مدل‌ها را بارگذاری مجدد نمی‌کند. هنگام تعویض، ورودی قبلی آزاد و مدل قبلی روی زمین پارک می‌شود. سرعت راه‌رفتن/دویدن هر دو مدل ۵/۹ متر بر ثانیه است؛ فیزیک پرش آواتار ترکیبی همان مقدار پذیرفته‌شدهٔ V2 است.

## کد و دارایی

`src/App.tsx` میزبان انتشار و `HybridComparisonAvatar.tsx` مصرف‌کنندهٔ export واقعی Plugin هستند. `comparison.mjs` مالکیت کنترل و `hybrid-comparison.mjs` پروفایل حرکت پذیرفته‌شده را نگه می‌دارند. `LegacyComparisonAvatar.tsx` و `legacy-preview.mjs` فقط متریال clone مرجع V1 را اصلاح می‌کنند؛ مدل و کلیپ‌های منبع تغییر نمی‌کنند. `CompareApp.tsx` و `AvatarWebV2.tsx` برای بازیابی مقایسهٔ قدیمی V1/V2 حفظ شده‌اند.

`src/main.tsx` به‌طور پیش‌فرض App ترکیبی را باز می‌کند. کد تست تک‌آواتار قبلی در همان فایل و مسیر `?mode=single` حفظ شده است. `scripts/prepare-avatar-hybrid.mjs` فقط exportهای بستهٔ نصب‌شده را resolve می‌کند؛ V1 را بدون تغییر مقدار داده‌ها به glTF/binary/تصویر محلی تفکیک و دارایی‌های V2 را در `.public-production/` تولید می‌کند. `vite.production.config.ts` فقط همین دارایی‌ها و کاور را به `dist/` می‌برد؛ منابع آزمایش `public/motion-test/` وارد خروجی انتشار نمی‌شوند. پوشهٔ تولیدی از Git کنار گذاشته شده است. ساخت میزبان به مسیر آزمایش یا cache ورودی مالک وابسته نیست.

نمونهٔ پذیرفته‌شده در `src/HybridTestApp.tsx`، `HybridTestAvatar.tsx`، `experiments/hybrid-v2-face/` و `dist-hybrid-test/` جدا و محفوظ است. این فایل‌ها ورودی انتشار نیستند و در کیت مستقل میزبان لازم نیستند. build عادی فقط `dist/` را تولید می‌کند.

## شواهد و ادامه

مالک نمونهٔ ترکیبی را پذیرفته و در ۲۰ اکتبر آماده‌سازی نسخهٔ الامر و Git را خواسته است. در این آماده‌سازی، آزمون‌های ساختاری و برابری بسته انجام می‌شوند؛ تست نمایشی پذیرفته‌شده تکرار نمی‌شود. آزمون‌های میزبان شامل قرارداد Player Rig، تعویض کنترل، فیزیک ترکیبی و برابری بایت‌های داراییِ آماده‌سازی‌شده با بستهٔ Plugin هستند. وضعیت و شواهد جاری در [گزارش مرحلهٔ دوم](../AVATAR_HYBRID_PHASE2_FA.md) و [تحویل پروژه](../PROJECT_HANDOFF.md) ثبت می‌شوند.

منابع چهار آواتار و محیط تحویل‌شده را حفظ کنید. مدیریت فهرست plugins با ابزار رسمی الامر است. `alamr dev` پیش‌نمایش محلی و `alamr test` بارگذاری candidate انتشار است؛ این دو را جایگزین هم نکنید. ثبت GitHub مجوز ارسال Registry نمی‌دهد. پیش از تغییر، AGENTS.md، skill محصول و مستندات دقیق `.al-amr/docs/plugins` را بخوانید.
